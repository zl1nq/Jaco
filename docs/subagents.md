# 子任务使用指南

[返回文档目录](README.md) · [项目首页](../README.md)

`explore` 子 agent 只能使用 `read_file`、`list_dir`、`grep`、`find_files`、`recall`、`git_status`、`git_diff`；`edit` 在此基础上增加 `write_file` 和 `edit_file`。两者均不能执行 shell、联网、管理后台进程或递归创建子 agent。每次运行拥有唯一 ID、独立消息、token/压缩状态及 `<父会话 ID>-sub-<UUID>.archive.jsonl` 归档；不生成可切换的会话记录。子任务的 `recall` 只读取本次归档，不能读父会话或其他子任务归档。中间探索不进入父会话上下文，最终报告作为工具结果返回；失败时附带有界的部分进展。

当前内置预设为 `explore`（默认，只读调查）和 `edit`（文件修改），由 `SubagentProfile` 集中定义系统提示和不可变工具白名单。主 agent 调用 `task` 时选择预设，并可进一步收窄工具范围。

| `task` 参数 | 规则 |
| --- | --- |
| `prompt` | 必填、非空字符串；任务目标、范围和报告要求，需要自包含 |
| `profile` | 可选字符串，支持 `explore`、`edit`，默认 `explore`；未知名称或非字符串拒绝启动 |
| `tools` | 可选字符串数组；省略使用该预设完整工具集，`[]` 表示不使用工具，重复项去重 |
| `run_in_background` | 可选 boolean，默认 `false`；`true` 立即返回任务 ID，后台完成后通知；仅支持 `explore`，与 `edit` 组合会拒绝启动 |

例如，仅允许读取和搜索文件：

```json
{"prompt":"调查配置加载逻辑，引用文件和行号", "profile":"explore", "tools":["read_file","grep","find_files"]}
```

`tools` 必须全部属于所选预设。未知工具、不属于所选预设的工具以及混合越权请求会整体拒绝，不会忽略非法项或回退到完整工具集；`null` 不能代替省略参数。工具子集在启动前验证并固定，模型可见工具和执行入口使用同一份不可变集合；即使模型调用了预设中存在但本次未授权的工具，也会拒绝。显式空集不会退回默认工具集。原来的 `{"prompt":"调查任务"}` 调用继续兼容。

`/subagents` 列表显示 `[explore]` 或 `[edit]` 和本次工具数量，详情展示固定的工具名称；edit 详情还显示审计日志路径。工具调用摘要也显示预设和请求的工具范围。仅选择预设和子集不改变原有的启动确认、生命周期、单活动任务及归档隔离规则。

`edit` 调用示例：

```json
{"prompt":"修改配置解析边界情况，补充测试代码，报告改动；不要声称已运行测试", "profile":"edit", "tools":["read_file","edit_file","write_file"]}
```

父子任务共用准备计划、修改预览、权限 hook 和结果审计入口。批准启动 `task` 不会自动批准写文件；子任务文件修改的预览、确认和结果都标注任务 ID。`y` 仅批准本次操作，`a` 沿用现有会话级工具放行规则，即使已放行仍展示每次修改预览。无可用确认渠道时拒绝子任务写入，`expected_version` 和预览后的文件快照检查保持生效。取消或超时后迟到的授权不能恢复写入；已完成的修改不自动回滚。子任务没有命令工具，测试和构建需由主 agent 在现有权限下执行。

每个 edit 任务在会话目录追加独立的 `<父会话 ID>-sub-<UUID>.audit.jsonl`：记录任务归属、预设、实际工具集、调用序号/ID、工具名、准备预览、权限允许/拒绝及结果（成功、拒绝、取消或失败）。参数和结果各保留最多 4096 字符，预览最多 8000 字符，并记录完整文本的 SHA-256 和截断标志；路径和预期版本单列。审计不是完整文件备份。执行前审计记录失败会阻止写入；执行后记录失败会结束子任务并报告此前修改，不能声称已经回滚。日志独立于对话归档，不作为子任务 recall 输入，也不随内存结果淘汰自动删除。

后台调查示例：

```json
{"prompt":"调查配置加载逻辑，引用文件和行号", "profile":"explore", "run_in_background":true}
```

后台调用只向原始 `task` 返回一次启动回执，完成后不会追加第二个工具结果或自动发起模型轮次。通知包含任务 ID、退出原因、耗时及查询方式；在输入期间通过行编辑器显示并保留未提交输入，在主任务运行期间由事件循环显示。主 agent 可在后续调用 `task_status`（`{"task_id":"完整任务ID"}`）取得报告，或使用 `task_cancel` 取消；用户可用 `/subagents` 查询、`/subagents cancel <ID>` 取消。后台任务仍有总超时和迭代预算，普通父轮结束或 Ctrl+C 不停止已登记的后台任务；新建或成功切换会话、应用退出会清理任务，不向其他会话投递通知。任务及通知不跨应用重启恢复，通知队列最多保留 32 条，完整结果遵循现有记录淘汰规则。后台读取与主任务修改共享工作区，报告可能反映读取时刻的文件内容。

子任务以“逻辑进程”管理：记录来源父会话和父轮次，状态为 `CREATED`、`QUEUED`、`RUNNING`、`CANCELLING`、`EXITED`；退出原因独立区分成功、失败、取消、超时、预算耗尽和应用关闭。`task` 默认同步等待结果，仅 `explore` 可选择后台运行；每个应用实例最多一个活动子任务，已有任务仍在运行或取消时，新任务直接拒绝，当前不提供等待队列或并行子任务调度。

整体超时默认 300 秒，覆盖模型请求、工具执行和上下文压缩。父轮取消会停止同步子任务；新建会话、成功切换到其他会话及退出应用会停止所属的同步和后台子任务；切换失败或切换到当前会话不影响任务。取消会中断执行线程、关闭已登记的模型流（包括摘要请求），并尽力终止受管工具进程。同步取消等待最多 2 秒；未确认执行线程和取消清理线程退出时保留 `CANCELLING` 及活动槽位，父调用返回“仍在取消中”，不会伪装成已退出。Java 同进程线程不能安全强杀，应用关闭也只进行有时限的清理。

`/subagents` 列出当前会话的任务 ID、状态、阶段、迭代数和已知 token 用量；`/subagents <完整任务 ID>` 查看最终结果。用量包含子任务调查与压缩请求，仅统计服务端已返回的 usage，缺失时显示未知。成功报告最多保留 16000 字符，超出时明确标记截断；失败、取消和超时保留最多 4096 字符的部分进展。每个实例最多保留 32 条已退出记录，读取不删除记录，最早完成的记录先淘汰；活动记录不淘汰。运行状态和最终结果仅保存在内存中，应用重启后不恢复，淘汰结果不删除归档。详细实现约定见 [子任务生命周期设计](subagent-lifecycle.md)。

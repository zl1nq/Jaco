# 跨会话用户画像

[返回文档目录](README.md) · [项目首页](../README.md)

用户画像默认开启，独立于会话保存。每轮以 `stop` 正常完成后，根据本地规则决定提取时机：明确表达（如“以后默认中文”“我是 Java 开发者”“忘记我的职业”）立即提取；普通消息先加入持久队列，当前项目累计 10 条时批量提取一次；“继续”“好的”“谢谢”等纯确认消息直接跳过。筛选规则只决定调用时机，是否构成长期信息仍由当前配置的模型判断。正常提取和更新静默执行，不显示进度或“已记住”条目；失败批次丢弃数量及错误类型仅写日志，无法保存批次清理结果时才显示简短提示。后续请求、新会话和重启后使用新画像。提取结果不进入会话消息，提取调用的 token 使用量计入触发它的对话或补处理操作的统计。

立即提取按本地意图规则判断，不把“默认”“以后”等单词本身作为触发条件，也不枚举职业名称。“长期表达 + 回复或工作行为”才触发偏好提取；自我介绍支持“我是一名……”“我从事……工作”等通用句式，裸“我是……”排除“我是来问问题的”“我是说这个方法”等明显任务表达。明确记住、忘记和个人信息纠正优先处理；直接的偏好请求问句仍可触发，自我信息查询不会仅因出现“我的职业”等词而触发。

| 用户表达 | 本地处理 |
| --- | --- |
| “这个参数默认是多少？”、“把接口超时默认值改成30秒” | `BATCH`，进入普通待处理队列 |
| “默认返回中文字符串”、“默认使用中文编码” | `BATCH`，避免将配置描述误作回复偏好 |
| “默认用中文回答我”、“以后能不能都用中文回复？” | `IMMEDIATE`，立即提取 |
| “这个项目以后统一用 Maven” | `IMMEDIATE`，模型判断是否为项目偏好 |
| “我是一名摄影师”、“我从事园艺工作” | `IMMEDIATE`，无需职业名单 |
| “记住我的称呼是小林”、“更正一下，我现在做产品设计” | `IMMEDIATE`，明确记忆或纠正请求 |
| “好的”、“继续” | `SKIP`，不入队 |

触发匹配前排除 Markdown 反引号/波浪线代码块、缩进代码、行内代码、`>` 引用及带明确说话来源的引号内容，保留“以后称呼我‘小林’”这类正常称呼。过滤仅作用于触发判断，普通含糊消息和引用原文仍可进入批量队列，最终语义判断和证据校验继续使用原始消息。本地规则可能漏选或误选，不保证理解所有自然语言表达；判断结果和原因码只记录在 DEBUG 日志，不增加模型分类调用，也不在正常回复中展示。规则及原因码集中在 [ProfileExtractionPolicy](../src/main/java/com/jaco/memory/ProfileExtractionPolicy.java)。

画像只用于自然适配回答，回复守则要求模型在用户未主动询问时，不主动提及画像、记忆库或加载过程，也不列举用户信息或用“根据你的画像”等解释回答依据。用户主动询问已记住的信息或使用 `/memory` 时，可以查看相关内容；明确要求记住或忘记时可简短确认需求，但不宣称尚未实际完成的保存或删除。该回复约束通过系统提示词实现，最终措辞仍取决于模型遵循情况。

终端执行 `/new`、有效切换到其他会话或通过 `/exit` / Ctrl+D 退出时，补处理当前项目剩余消息。失败切换及切换当前会话不补处理。补处理可用 Ctrl+C 取消：新建或切换会话会取消，退出时仍可退出，队列保留。异常退出后尚未处理的队列恢复，之后达到批量阈值、出现明确表达或执行上述边界操作时继续处理，不在启动时自动请求模型。每个批次只尝试一次：网络失败、超时、输出不完整或校验失败都会直接丢弃本批，然后继续处理后面的批次，不设置冷却或重试。当前立即提取与普通批量提取共用队列，因此立即提取所在批次失败时也会丢弃，允许少量漏记。旧文件中的 `retryAfter` 字段被忽略，下一次写入时移除。

批次按用户发言顺序处理，操作必须携带具体消息 ID，原话证据只能来自该条消息；来源会话也由程序确定。成功提取（包括没有画像变化的空结果）在一次原子写入中保存画像并移除已处理消息。失败时不保存本批提取结果，单独原子移除本批候选，保留原画像、后续批次及其他项目的候选；用户取消时不移除消息。如果磁盘写入失败、无法保存丢弃结果，则保留内存状态并停止本次处理，避免反复处理同一批。不同项目不混在同一批次中；其他项目较早的候选也不能覆盖较新的全局偏好或重建已经自动删除的条目。

全局信息适用于所有项目；明确限定“这个项目”的偏好绑定当前工作目录的真实路径，同类别同键的项目偏好覆盖全局偏好。当前用户明确要求优先于已有画像；画像不能授予工具权限或跳过确认。切换会话和 `/new` 不清除画像，删除会话也不删除画像；画像中的来源会话 ID 因此可能指向已删除的会话。

聊天请求采用“固定常驻项 + 当前任务相关项”，通过本地规则选择，不额外调用模型。常驻项仅包括偏好类的 `response.language`、`response.length`、`response.tone` 和信息类的 `identity.preferred_name`；职业、技术背景、提交习惯等不会因最近更新而自动常驻。

| 当前任务 | 按需加载的画像键 |
| --- | --- |
| 提交代码、Git commit | `git.commit_style`、`git.commit_behavior` 和 `git.*` |
| Java / JavaScript / TypeScript 开发 | 对应的 `code.java.*` / `code.javascript.*` / `code.typescript.*`，以及通用代码偏好 |
| 修改代码、重构、运行测试 | 通用 `code.*`、`code.testing.*`、`identity.familiar_tech`；语言专属键只在对应语言命中时加载 |
| 编写文档、README | `document.*` |
| 明确询问自己的信息或偏好 | 个人信息及尚未映射的键，仍受总长度限制 |

当前用户原始输入决定任务类别，中文短语与英文标识符匹配可同时命中多个类别；英文匹配区分 Java 与 JavaScript。纯承接语（如“继续”“按刚才的方案做”）沿用上一轮任务类别，明确新任务或普通问候重新匹配；重启和切换会话从目标会话最近的实质用户输入恢复类别，`/new` 清空类别。助手回复和工具输出不参与任务识别。规则只做词语匹配，可能漏选或误选，扩展入口见 [ProfileContextSelector](../src/main/java/com/jaco/memory/ProfileContextSelector.java)。

发送的画像使用简短的 `key: "value"` 行，只保留键与 JSON 字符串值，不发送 ID、类别、范围路径、证据或时间。选择顺序为常驻项、直接相关项、通用相关项，更新时间只用于同等相关性排序；先用当前项目值覆盖全局同键值，再选择条目。常见旧键名在加载和更新时归一化，例如 `reply.language` → `response.language`、`identity.name` → `identity.preferred_name`，无需手动改写旧画像文件。

提取器仅以队列中的用户原始消息为证据，每条消息之前的助手回复（最多 2,000 字符）只用于理解指代。模型被要求忽略引用、第三方信息、假设、角色扮演、临时要求（如“这次详细解释”）以及密码、密钥等凭据，不推断用户性格或身份。正式画像记录保存类别、稳定键、值、作用范围、来源会话、原话证据和更新时间；明确纠正用新值覆盖，明确要求忘记则删除。语义判断依赖当前模型，原文证据校验不能保证分类完全准确，发现误记可用 `/memory forget <ID>` 删除。

画像最多保存 64 条，每条值最多 240 字符，每批最多 16 个操作；超过容量时整批更新失败，保留原画像并丢弃本批候选。每次聊天请求注入的画像正文最多 2,000 字符，保留完整条目，不截断值。待处理队列最多 100 条、合计 100,000 字符（含每条助手上下文）；单条用户输入超过 16,000 字符或队列达到上限时，本条不入队并提示，已有队列保留。每批最多 10 条、合计 20,000 字符，长消息会拆成多批；立即提取和边界补处理可能因此需要多个请求，按顺序处理，失败批次丢弃后继续。画像提取每批共用 60 秒总预算，从请求前开始计时，连接、等待响应头、HTTP 重试及退避、错误正文读取和流式读取都消耗同一预算，重试和新内容片段不重置时间；本地结果校验和落盘不受此网络预算限制。超时会取消请求、关闭响应流并丢弃本批，用户 Ctrl+C 取消则保留批次。HTTP 客户端既有最多三次尝试策略保持不变，所有尝试均受总预算限制；普通聊天不使用画像提取的 60 秒截止时间。多个批次各自计算预算，补处理整个流程没有额外的总时长上限。提取失败不影响已经完成的聊天回复。提取仍携带全局和当前项目已有条目，以便识别更新和删除。

`/memory` 同时显示当前项目待处理消息数。`off` 停止额外提取调用与画像加载，保留正式画像，丢弃全部项目的待处理候选；`on` 恢复，不补录关闭期间的消息。手动 `forget` 成功删除条目或 `clear` 清空画像时，同样清理全部旧候选，避免以后批处理又记回被删除的信息。画像不会自动扫描旧会话，也不会因删除画像而抹去旧会话消息中的信息，当前会话仍可能提及这些信息；需要排除旧上下文时可再 `/new`。

画像和候选原始消息都在 `user-profile.json` 中以明文保存。候选消息尚未经过模型过滤，因此可能含原始输入中的个人信息或凭据；上述排除规则针对正式画像条目。提取时发送该批用户消息、对应助手上下文以及全局/当前项目的已有画像到当前模型服务，聊天时发送相关画像。旧画像文件无需手动迁移；文件损坏时本次启动停用画像并保留原文件，修复后重启。

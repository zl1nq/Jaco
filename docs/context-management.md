# 上下文管理

[返回文档目录](README.md) · [项目首页](../README.md)

JACO 用两层机制控制发送给模型的上下文体积：

1. **单条工具输出归档**：主任务和子任务共用同一入口，超过 `max_tool_result_chars` 时先完整写入所属归档，再回填头尾预览。只有写入成功才提示可用 `recall` 找回；失败时明确说明仅剩预览、需要缩小范围重新读取。提示和省略标记计入总字符预算，裁剪不切断 Unicode 代理对。
2. **请求前压缩**：每次模型请求前检查上下文体积，取最近真实 prompt tokens 与本地消息估算的较大值，超过 `context_limit` 的 70% 时触发，目标压至 40%。先处理旧用户轮：旧工具结果替换为简短占位后若已达标，先归档原文再更新消息；若仍未达标，则归档旧轮并留下骨架摘要，必要时使用模型摘要兜底。单轮内持续执行工具时，进一步按 assistant 调用与全部 tool results 组成完整迭代组，归档旧组并留下进展摘要，保留系统提示、原始任务及最近两组。归档失败的阶段保留其输入消息；已压缩工具结果状态随父会话保存。

旧轮压缩优先保护最近两轮，迭代压缩始终保留工具调用与全部结果的配对。摘要输入及输出均有长度上限，支持取消并关闭请求流；无法达到目标比例时保留最近完整交互。归档可通过 `recall` 检索：搜索用 `query`（Java 正则）、`offset`、`limit`，返回条目 ID、总长度和命中附近预览，`offset` 是匹配结果列表偏移；读取全文用 `entry_id`、`content_offset`、`content_limit`，保留原文换行，内容偏移按 Java UTF-16 单位计数。单次返回受 `max_tool_result_chars` 限制，按下一页参数继续读取，读取模式不要混用搜索参数。服务端报告超限时，允许保留最近一组并强制压缩，只有本地消息体积确实减小才重试，单次执行最多重试一次；无法缩小则结束，保留现有进展。

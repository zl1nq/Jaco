# 子任务生命周期

子 agent 是同一 JVM 中的逻辑进程，独立上下文和归档，共享只读工具与工作区。第一阶段保留同步 `task(prompt)` 协议，一个应用实例只接收一个活动子任务，暂不支持排队等待、并行、递归委派、挂起恢复或跨父轮后台运行。

## 组成

| 类型 | 职责 |
| --- | --- |
| `SubagentSpec` | 固定父会话、父轮 ID、任务说明、总超时和迭代预算 |
| `SubagentManager` | 注册、准入、监督执行、按父归属取消、关闭和记录淘汰 |
| `SubagentHandle` | 暴露只读快照、停止请求及等待结果，不暴露可修改 Future |
| `SubagentControl` | 同步状态变更、裁定完成竞争、登记资源和统计 |
| `SubagentRunner` | 独立模型和只读工具循环，使用启动时固定的依赖 |
| `SubagentResult` | 有界报告、部分进展、错误摘要及运行统计 |
| `AgentLoopSupport` | 父子循环共用流消费、工具结果归档和上下文压缩 |

`TurnHandle.id()` 是父轮标识。正常入口在父线程固定会话和轮次信息；直接调用 `runSubagent` 的嵌入场景分配临时轮次 ID，以传入的取消信号建立作用域。模型、工具沙箱等不可变执行依赖由 runner 持有，运行中不读取父会话字段。

## 状态和退出原因

| 原状态 | 事件 | 新状态 |
| --- | --- | --- |
| `CREATED` | 注册完成 | `QUEUED` |
| `QUEUED` | 获得执行槽位 | `RUNNING` |
| `CREATED` / `QUEUED` | 取消或截止时间已到 | `CANCELLING`，不执行模型或工具，清理确认后进入 `EXITED` |
| `RUNNING` | 接受正常结果或异常结果 | 清理完成并确认线程结束后进入 `EXITED` |
| `RUNNING` | 请求取消、到期或关闭 | `CANCELLING` |
| `CANCELLING` | 执行及取消清理线程均已结束 | `EXITED` |

阶段独立记录为 `IDLE`、`REQUESTING_MODEL`、`EXECUTING_TOOL`、`COMPACTING_CONTEXT`、`CLEANING_UP`。等待模型响应属于运行中的工作阶段，不模拟操作系统 CPU 时间片状态。

退出原因分为 `SUCCEEDED`、`FAILED`、`CANCELLED`、`TIMED_OUT`、`BUDGET_EXCEEDED`、`SHUTDOWN`。停止请求另记来源：用户取消、父轮取消、父作用域关闭、会话切换、超时或应用关闭。首次接受的停止来源不被后续停止请求覆盖。

完成结果和停止请求在控制块同一监视器下裁定。停止请求先被接受时，不允许迟到的成功覆盖停止结果；结果先被接受时，后续取消仍能推动清理，但不改写已选的完成原因。清理异常可将成功改为失败。结果至多发布一次，发布前由监督线程确认执行线程和取消清理线程均已结束，随后释放活动槽位。

## 取消与资源

正常模型流和摘要流都登记到控制块。登记与停止竞争时，登记方检查停止状态并立即关闭迟到的流；清除资源时必须按实例匹配，旧请求不能清掉新请求。工具上下文使用本次任务自己的进程引用和取消信号。

停止操作幂等，发出线程中断，并在独立、受监督的虚拟线程中关闭模型流和尽力终止受管工具进程，防止响应体关闭阻塞 TUI。执行线程在 `finally` 中再次进行幂等清理。Java 线程没有安全强杀机制，进程树终止也受平台权限约束。

总预算从接收任务开始，使用单调时钟判断。监督线程处理阻塞期间的超时；执行边界直接检查父取消和剩余时间；接受结果时再次检查截止时间，避免依赖监督线程的调度时机。取消宽限时间为 2 秒，超期保留活动槽位并标记清理超时，不将任务标记为已退出。

## 父作用域与会话

父轮取消立即通知所属任务，父执行作用域离开时取消异常遗留任务。界面收到取消结束事件，只意味着交互结束，不代表执行资源已释放。旧父轮持有自己的会话对象，迟到的工具结果只写回原会话；子任务中间消息始终不进入父会话。

新建会话或成功切换到不同会话时取消原会话活动任务；切换失败或切换到当前会话不取消。当前会话只能通过 `/subagents` 查询自己的任务结果。应用关闭先拒绝新任务，再取消活动任务并限时等待；重复关闭安全。

## 结果保留与统计

结果统计包含运行耗时、调查迭代数和服务端已返回的 token 用量。压缩请求计入时间和 token，单独的调查迭代预算不计摘要请求。缺失 usage 不按已知零用量展示；中断请求的未返回用量无法推算。第一阶段不实现 token 硬预算。

成功报告上限 16000 字符，截断明确标记；部分进展上限 4096 字符，错误摘要上限 512 字符，避免拆开 Unicode 代理对。退出后释放原始 prompt、消息、线程、流及父取消回调等引用，只保留身份、状态、统计及有界结果。

最多保留 32 条已退出记录，按完成顺序淘汰，不删除活动记录；读取结果不消费记录。记录只在内存保存，归档沿用原有文件格式，淘汰记录不删除归档。

## 验证边界

测试覆盖启动前取消、取消与流登记竞争、清除旧流、完成与取消竞争、清理延迟和清理异常、阻塞超时、预算耗尽、用量合并、记录淘汰、会话切换及迟到结果隔离。强制结束 JVM、操作系统拒绝终止进程、永久不响应取消的第三方代码均无法保证清理完成。

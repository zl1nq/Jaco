<h1 align="center">JACO</h1>

<p align="center"><em>JAVA CODER</em></p>

<p align="center">用 Java 21 从零构建的终端 AI 编程助手</p>

> JACO 将模型对话、工具调用和权限确认串成完整的 agent 循环。 你可以在终端中让它阅读代码、修改文件、执行命令，或委派只读子 agent 调查问题。模型通过 OpenAI 兼容的 Chat Completions 接口接入，核心 agent 与终端界面独立，便于扩展工具和交互方式。

## 功能概览

- **终端交互**：流式输出、等待动画、Markdown 渲染、代码高亮与中文表格对齐。
- **工具调用**：读写文件、浏览目录、搜索代码、执行命令、检索归档与委派子任务。
- **权限控制**：只读工具自动放行，写入、命令执行和子任务需确认；支持按工具在当前会话内放行。
- **会话管理**：自动保存和恢复会话，支持查看历史、切换会话与中断当前任务。
- **上下文管理**：大工具输出自动归档，长对话分层压缩，保留可检索的原始历史。

## 快速开始

### 1. 构建

需要 **JDK 21 或更高版本**和 **Maven**。在项目根目录执行：

```bash
mvn package
```

构建后生成包含运行依赖的 `target/jaco.jar`。

### 2. 配置模型

首次执行以下命令会输出配置示例；请手动创建 `~/.jaco/config.yaml`，然后重新启动：

```bash
java -jar target/jaco.jar
```

Windows 下默认配置路径为 `%USERPROFILE%\.jaco\config.yaml`。设置 `JACO_HOME` 可以更改配置、会话和日志所在的数据目录。

以 DeepSeek 为例：

```yaml
active: deepseek
providers:
  deepseek:
    base_url: https://api.deepseek.com
    api_key: ${DEEPSEEK_API_KEY}
    model: deepseek-chat
    temperature: 0.7
```

在启动 JACO 的终端中设置 API Key。

**PowerShell：**

```powershell
$env:DEEPSEEK_API_KEY = "你的 API Key"
```

**Bash / Zsh：**

```bash
export DEEPSEEK_API_KEY="你的 API Key"
```

### 3. 开始对话

```bash
java -jar target/jaco.jar
```

**启动时所在的目录就是工作目录。** 如需操作其他项目，先进入目标目录，再使用 JAR 的绝对路径启动：

```bash
cd /path/to/your-project
java -jar /path/to/jaco/target/jaco.jar
```

进入交互界面后，直接输入任务，例如：

```text
帮我梳理这个项目的结构，并说明入口和核心模块。
检查配置加载逻辑，找出可能导致启动失败的原因。
帮我修改这个方法，并运行相关测试。
```

## 交互与权限

### 命令与快捷键

| 命令 / 快捷键 | 作用 |
| --- | --- |
| `/help` | 显示可用命令 |
| `/new` | 创建新会话，清空当前上下文与权限放行记录 |
| `/sessions` | 按新到旧列出会话 ID、标题和消息数，`*` 标记当前会话 |
| `/switch <会话 ID>` | 切换会话并清空权限放行记录，支持唯一 ID 前缀 |
| `/delete <会话 ID>` | 删除历史会话及归档，支持唯一 ID 前缀；需确认，不能删除当前会话 |
| `/memory` | 查看用户画像、条目 ID、类别和作用范围 |
| `/memory forget <ID>` | 删除指定画像条目，使用完整 ID |
| `/memory clear` | 确认后清空全部画像，包含所有项目 |
| `/memory off` / `/memory on` | 关闭 / 开启自动记忆与画像加载，设置随画像持久保存 |
| `/exit` 或 `Ctrl+D` | 退出 |
| `Ctrl+C` | 中断当前轮：取消模型流、终止命令子进程、拒绝待确认操作；已生成内容保留进会话 |

启动时自动恢复最近一次会话；没有历史会话时创建新会话。

会话标题自动取首次有效用户输入的前 40 个字符，合并空白并在超长时添加省略号，无需额外请求模型。标题随会话保存，后续输入和上下文压缩不改变标题；旧会话从尚存的首条用户消息提取标题，无有效输入时显示“未命名会话”。切换会话仍使用 ID。

`/delete` 会展示目标 ID 和标题，输入 `y` 后删除对应会话 JSON 和归档 JSONL，操作不可恢复；其他输入、`Ctrl+C` 或 `Ctrl+D` 均取消。删除当前会话前，请先 `/switch` 或 `/new`；前缀不唯一时不会删除，也不支持批量删除。

新建会话或成功切换到其他会话后，需要重新确认工具授权；切回旧会话不会恢复此前授权。切换失败或切换到当前会话时，现有授权保持不变。

### 跨会话用户画像

用户画像默认开启，独立于会话保存。每轮以 `stop` 正常完成后，使用当前配置的模型额外调用一次，提取用户明确表达的个人信息和长期偏好，例如称呼、职业、熟悉的技术、默认回复语言和代码风格。新增或更新后显示简短提示；下一轮、新会话和重启后自动使用画像。提取结果不进入会话消息，提取调用的 token 使用量合并到本轮统计。

全局信息适用于所有项目；明确限定“这个项目”的偏好绑定当前工作目录的真实路径，同类别同键的项目偏好覆盖全局偏好。当前用户明确要求优先于已有画像；画像不能授予工具权限或跳过确认。切换会话和 `/new` 不清除画像，删除会话也不删除画像；画像中的来源会话 ID 因此可能指向已删除的会话。

聊天请求采用“固定常驻项 + 当前任务相关项”，通过本地规则选择，不额外调用模型。常驻项仅包括偏好类的 `response.language`、`response.length`、`response.tone` 和信息类的 `identity.preferred_name`；职业、技术背景、提交习惯等不会因最近更新而自动常驻。

| 当前任务 | 按需加载的画像键 |
| --- | --- |
| 提交代码、Git commit | `git.commit_style`、`git.commit_behavior` 和 `git.*` |
| Java / JavaScript / TypeScript 开发 | 对应的 `code.java.*` / `code.javascript.*` / `code.typescript.*`，以及通用代码偏好 |
| 修改代码、重构、运行测试 | 通用 `code.*`、`code.testing.*`、`identity.familiar_tech`；语言专属键只在对应语言命中时加载 |
| 编写文档、README | `document.*` |
| 明确询问自己的信息或偏好 | 个人信息及尚未映射的键，仍受总长度限制 |

当前用户原始输入决定任务类别，中文短语与英文标识符匹配可同时命中多个类别；英文匹配区分 Java 与 JavaScript。纯承接语（如“继续”“按刚才的方案做”）沿用上一轮任务类别，明确新任务或普通问候重新匹配；重启和切换会话从目标会话最近的实质用户输入恢复类别，`/new` 清空类别。助手回复和工具输出不参与任务识别。规则只做词语匹配，可能漏选或误选，扩展入口见 [ProfileContextSelector](src/main/java/com/jaco/memory/ProfileContextSelector.java)。

发送的画像使用简短的 `key: "value"` 行，只保留键与 JSON 字符串值，不发送 ID、类别、范围路径、证据或时间。选择顺序为常驻项、直接相关项、通用相关项，更新时间只用于同等相关性排序；先用当前项目值覆盖全局同键值，再选择条目。常见旧键名在加载和更新时归一化，例如 `reply.language` → `response.language`、`identity.name` → `identity.preferred_name`，无需手动改写旧画像文件。

提取器仅以本轮用户原始消息为证据，上一条助手回复（最多 2,000 字符）只用于理解指代。模型被要求忽略引用、第三方信息、假设、角色扮演、临时要求（如“这次详细解释”）以及密码、密钥等凭据，不推断用户性格或身份。记录保存类别、稳定键、值、作用范围、来源会话、原话证据和更新时间；明确纠正用新值覆盖，明确要求忘记则删除。语义判断依赖当前模型，原文证据校验不能保证分类完全准确，发现误记可用 `/memory forget <ID>` 删除。

画像最多保存 64 条，每条值最多 240 字符，每轮最多 16 个操作；超过容量时整批更新失败，保留原记录，可删除不需要的条目后继续。每次聊天请求注入的画像正文最多 2,000 字符，保留完整条目，不截断值。本轮输入超过 16,000 字符时跳过提取；流式提取等待最多 30 秒（不含建立 HTTP 请求的等待），Ctrl+C 可中断提取。失败、未正常结束或结果无效时保留原画像，不影响已经完成的聊天回复。上述选择只优化聊天请求的画像输入量；每轮正常完成后的画像提取调用次数保持不变，提取仍携带全局和当前项目已有条目，以便识别更新和删除。

`/memory off` 停止额外提取调用与画像加载，但保留已有记录；`on` 恢复。画像不会自动扫描旧会话，也不会因删除画像而抹去旧会话消息中的信息，当前会话仍可能提及这些信息；需要排除旧上下文时可再 `/new`。画像 JSON 以明文保存在本地；提取时会发送本轮用户消息、上述上一条助手回复及全局/当前项目的已有画像到当前模型服务，聊天时发送相关画像。画像文件损坏时，本次启动停用画像并保留原文件，修复后重启。

### 内置工具

工具由模型根据任务调用，无需手动输入工具名。

| 工具 | 用途 | 默认权限 |
| --- | --- | --- |
| `read_file` | 带行号读取文件，支持分页 | 自动放行 |
| `list_dir` | 浏览目录 | 自动放行 |
| `grep` | 搜索文件内容 | 自动放行 |
| `recall` | 搜索当前会话归档、预览命中片段，按条目 ID 分页读取原文 | 自动放行 |
| `write_file` | 严格校验参数后，以 UTF-8 原子新建或覆盖文件 | 需确认 |
| `edit_file` | 精确唯一匹配原文，原子替换已有文件中的一个片段 | 需确认 |
| `run_command` | 在工作目录执行 shell 命令，返回合并输出与退出码 | 需确认 |
| `task` | 委派具有独立上下文的只读子 agent，返回最终调查报告 | 需确认 |

确认提示支持：

| 输入 | 含义 |
| --- | --- |
| `y` | 仅允许本次调用 |
| `a` | 在当前会话内允许该工具的后续调用 |
| `n` | 拒绝调用，拒绝结果反馈给模型 |

命中危险命令黑名单的调用会直接拒绝，不能通过 `y` 或 `a` 放行。

`write_file` 接受 `path`、`content` 和 `expected_version`：路径必须是非空白字符串，内容必须显式提供字符串（空字符串表示空文件）。写入先在目标目录生成临时文件，完成后原子替换目标；失败时尝试清理临时文件。文件系统不支持原子替换时会报错，不降级为直接覆盖。已有文件的 POSIX 权限在支持的平台上保留。

修改已有文件优先使用 `edit_file`，参数为 `path`、`old_text`、`new_text` 和 `expected_version`。原文必须非空且精确唯一匹配（包括空白和换行，不含 `read_file` 输出的行号）；未找到或存在多处匹配时不修改文件，应重新读取或增加定位上下文。`new_text` 可为空以删除片段，不支持批量替换或创建新文件；修改使用与 `write_file` 相同的原子写入流程。

`read_file` 返回基于完整原始字节的 SHA-256 文件版本（分页读取也使用整个文件版本）。修改已有文件必须将该版本传入 `expected_version`，省略、格式错误或版本不匹配均拒绝修改；新建文件可省略版本。每次写入后返回新的版本，可用于下一次修改；文件已删除时不能沿用旧版本重建。空文件也可读取并取得版本。

`write_file` 和 `edit_file` 在权限确认前展示行级修改预览：绿色 `+` 为新增、红色 `-` 为删除，附上下文、旧/新行号、行数统计与换行格式。最多展示 80 行，长行最多 200 个字符，总体约 8,000 字符；超限会明确提示截短，确认后仍执行完整计划。较大的变化区间采用整段对比以控制计算量。会话内已放行的工具也展示预览。准备预览不会写入文件；执行时及原子替换前检查原文快照，发现文件已变化或新文件已被创建时拒绝覆盖，提示重新读取。

文件工具的路径访问限定在工作目录及 `workspace.extra_roots` 中。`run_command` 使用本机 shell 执行，这个文件路径限制不构成命令进程的系统级沙箱。命令超时为 120 秒；输出读取量受限，回填最多保留末尾 50,000 字符，再经过单条工具输出的归档处理。

子 agent 只能使用只读工具，不能写文件、执行命令或递归创建子 agent；中间探索过程不进入父会话上下文，最终报告作为工具结果返回。

## 配置参考

### 模型服务

在 `providers` 中定义命名配置，通过 `active` 选择启动时使用的配置；只有一个配置时可以省略 `active`。

服务需兼容 OpenAI Chat Completions 的流式响应与工具调用协议。`base_url` 支持服务根地址、带 `/v1` 的地址或完整的 `/chat/completions` 地址；未包含 `/chat/completions` 时会自动追加该路径，请按服务实际接口填写。

配置中的 `${VAR}` 会从环境变量替换；未设置的变量会替换为空字符串。当前启动检查要求 `api_key` 非空，使用不需要鉴权的本地服务时也需填写一个非空占位值。未知配置字段会被忽略。

### 可选配置

以下字段与 `active`、`providers` 位于同一级：

```yaml
# system_prompt: 自定义系统提示词
log_level: INFO
shell: auto
max_iterations: 25
context_limit: 65536
max_tool_result_chars: 8000
workspace:
  extra_roots:
    - D:/other-project
```

| 字段 | 默认值 | 说明 |
| --- | --- | --- |
| `system_prompt` | 内置提示词 | 自定义系统提示词 |
| `log_level` | `INFO` | 日志级别，可设为 `DEBUG` 排查问题 |
| `shell` | `auto` | 支持 `auto`、`bash`、`cmd`、`powershell` |
| `max_iterations` | `25` | 单轮最大模型调用次数 |
| `context_limit` | `65536` | 上下文压缩的 token 基准，应按模型窗口调整 |
| `max_tool_result_chars` | `8000` | 单条工具输出的归档触发字符数 |
| `workspace.extra_roots` | 空列表 | 文件工具允许访问的额外目录 |

完整字段定义见 [JacoConfig](src/main/java/com/jaco/config/JacoConfig.java) 和 [ProviderConfig](src/main/java/com/jaco/config/ProviderConfig.java)。

### 数据存储

默认数据目录为 `~/.jaco/`；设置 `JACO_HOME` 后，下列路径随之迁移：

```text
~/.jaco/
├── config.yaml                  # 模型与运行配置
├── history                      # 终端输入历史
├── user-profile.json            # 跨会话用户信息、偏好与自动记忆开关
├── sessions/
│   ├── <会话 ID>.json            # 会话记录
│   └── <会话 ID>.archive.jsonl   # 压缩历史与大工具输出归档
└── logs/                        # 运行日志
```

日志写入文件，终端输出留给交互界面。

## 上下文管理

JACO 用两层机制控制发送给模型的上下文体积：

1. **单条工具输出归档**：超过 `max_tool_result_chars` 时，将该条输出完整写入归档，在对话中保留头尾预览与归档提示。
2. **轮级压缩**：每轮开始检查上下文体积，超过 `context_limit` 的 70% 时触发，目标压至 40%。先在临时消息中计算压缩结果：旧工具结果替换为简短占位后若已达标，先归档被替换的原文，再更新会话；若仍未达标，则归档旧轮并留下骨架摘要，必要时使用模型摘要兜底。归档失败时保留原会话；已压缩工具结果的状态随会话保存，避免重复归档和改写占位。

轮级压缩保护最近两轮，并保持工具调用与工具结果配对。归档保留原始内容，可通过 `recall` 检索。搜索用 `query`（Java 正则）、`offset`、`limit`，返回条目 ID、总长度和命中附近的预览；`offset` 是匹配结果列表偏移。读取全文用 `entry_id`、`content_offset`、`content_limit`，保留原文换行；内容偏移按 Java UTF-16 字符单位计数。单次返回受 `max_tool_result_chars` 限制，请按返回的下一页参数继续读取；读取模式不要混用搜索参数。若服务端报告上下文超限，会强制压缩并重试一次。

## 架构与扩展

项目按包划分职责，`llm` 和 `agent` 不依赖 `tui`。

| 包 | 职责 |
| --- | --- |
| `tui` | 基于 JLine 3 的 REPL，消费 `TurnEvent`，处理渲染、确认、命令和中断 |
| `agent` | `AgentRunner` 驱动工具循环与只读子 agent；`ContextCompactor` 管理压缩与归档 |
| `llm` | 手写 OpenAI 兼容 SSE 客户端，处理流式响应、工具调用增量、重试和取消 |
| `tool` | 工具接口与注册表、8 个内置工具、权限钩子和文件路径沙箱 |
| `render` | Markdown 流式渲染、代码高亮、表格对齐与 CJK 显示宽度计算 |
| `hook` | agent 生命周期钩子，可接入权限、审计与续轮逻辑 |
| `session` | 会话 JSON 保存、恢复与 JSONL 归档 |
| `config` | YAML 配置、环境变量替换与模型配置选择 |

主要扩展入口：

- **新增工具**：实现 `Tool` 接口并通过 `ToolRegistry.register()` 注册，无需修改 agent 循环。
- **生命周期钩子**：实现 `AgentHook`；`onStop` 返回 `true` 可以请求续轮。
- **渲染后端**：渲染器输出带语义颜色的 `Span`，终端使用 ANSI 后端，可据此扩展其他界面。

代码高亮支持 Java、Python、JavaScript、Bash 和 JSON，其他语言原样显示；终端颜色自动探测 truecolor，并可降级为 256 色。

## 开发与测试

```bash
mvn test
```

测试使用 JUnit 5，覆盖工具输出归档、上下文压缩、会话存储与切换、归档检索及只读子 agent 等行为。`mvn package` 会执行测试并打包可运行 JAR。

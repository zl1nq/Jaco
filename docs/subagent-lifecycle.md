# 子任务生命周期

子 agent 是同一 JVM 中的逻辑进程，独立上下文和归档，按预设使用工具并共享工作区。保留同步 `task` 协议，`prompt` 必填，支持可选的 `profile` 和 `tools`；一个应用实例只接收一个活动子任务，暂不支持排队等待、并行、递归委派、挂起恢复或跨父轮后台运行。

## 组成

| 类型 | 职责 |
| --- | --- |
| `SubagentProfile` | 内置不可变预设，集中定义标识、系统提示和工具白名单；当前为 `EXPLORE` 和 `EDIT` |
| `SubagentRequest` | 工具层到运行时的不可变请求，验证任务说明、预设和工具子集 |
| `SubagentSpec` | 固定父会话、父轮 ID、任务说明、预设、实际工具集、总超时和迭代预算 |
| `SubagentManager` | 注册、准入、监督执行、按父归属取消、关闭和记录淘汰 |
| `SubagentHandle` | 暴露只读快照、停止请求及等待结果，不暴露可修改 Future |
| `SubagentControl` | 同步状态变更、裁定完成竞争、登记资源和统计 |
| `SubagentRunner` | 独立模型和按预设限制的工具循环，使用启动时固定的依赖 |
| `SubagentResult` | 有界报告、部分进展、错误摘要及运行统计 |
| `ToolCallExecutor` | 父子循环共用工具准备、预览、权限确认和完成 hook |
| `SubagentAuditHook` | edit 子任务独立 JSONL 审计，记录准备、权限裁决和执行结果 |
| `AgentLoopSupport` | 父子循环共用流消费、工具结果归档和上下文压缩 |

`TurnHandle.id()` 是父轮标识。正常入口在父线程固定会话和轮次信息；直接调用 `runSubagent` 的嵌入场景分配临时轮次 ID，以传入的取消信号建立作用域。模型、工具沙箱等不可变执行依赖由 runner 持有，运行中不读取父会话字段。

现有只读调查能力位于 `SubagentProfile.EXPLORE`，对外标识为 `explore`。`task` 接收必填 `prompt` 以及可选 `profile`、`tools`。省略预设时使用 `explore`，省略工具子集时使用预设完整工具集，空数组表示禁止工具；未知预设、非法类型或任何越界工具均整体拒绝，不默默过滤或回退。另有 `edit` 预设，包含只读工具及 `write_file`、`edit_file`；两者都禁止 shell、网络、后台进程及递归 task。未开放自定义预设。

`TaskTool.Handler` 接收已验证的 `SubagentRequest`，传入 `AgentRunner.runSubagent(SubagentRequest, cancelled)`；原有 `runSubagent(String, cancelled)`、五参数和六参数 `SubagentSpec` 构造入口保留，默认行为不变。预设及实际工具集在请求与 Spec 边界都校验并复制为不可变集合，调用者修改原集合无法扩权。运行时使用实际集合生成模型工具定义及执行白名单；集合为空时不发送工具定义，并明确告知模型不得调用工具。

控制块在释放原始任务说明后仍保留预设标识和实际工具集，供 `/subagents` 查询运行中及已退出记录。列表展示工具数，详情展示排序后的工具名称，工具调用摘要展示选择范围，后续取消、超时和归档行为与预设选择解耦。

## 修改预览、权限和审计

父子任务使用 `ToolCallExecutor`：取消/工具范围检查 → `registry.prepare` → 同一修改计划的预览 → `onToolPrepared` → `onBeforeToolCall` 权限裁决 → `onToolPermission` → 再检查取消 → 执行计划 → `onToolCompleted`。完成 hook 默认调用原有 `onAfterToolCall`，旧观察点保持兼容。未授权的工具不会进入 prepare 或权限确认，但仍通知完成观察点，明确记录拒绝结果。后置 hook 失败不改变已发生的文件操作，也不阻止其他后置 hook 收到真实结果。

父线程捕获创建任务时的 `TurnEventSink`，子线程显式绑定有任务 ID 和子任务取消信号的作用域，退出时恢复槽位；不依赖线程上下文自动继承。文件写入的工具开始、预览、确认和结束事件带 `taskId`，TUI 标注子任务身份。普通探索事件保持静默，中间消息不进入父模型上下文。

子任务使用父权限策略：启动 task 的授权与 write_file/edit_file 分开；已有会话级放行继续有效，但仍逐次展示预览。没有确认渠道时子任务拒绝写入。取消和超时由子作用域感知，权限返回后及执行前再次检查，write_file/edit_file 的执行计划在写入和原子替换前检查取消及文件版本。会话切换的权限世代检查防止迟到的会话放行重新污染新会话。已完成的修改不自动回滚。

仅 edit 默认增加 `SubagentAuditHook`，输出到 `<父会话 ID>-sub-<UUID>.audit.jsonl`。记录父会话/轮次、任务 ID、预设和工具集、调用序号/ID、参数与预览、权限 ALLOW/DENY 及原因、执行 SUCCEEDED/DENIED/CANCELLED/FAILED。参数和结果各最多 4096 字符，预览最多 8000 字符，完整文本另附 SHA-256 和截断标志；路径和 expected_version 单列。审计不提供完整文件备份或崩溃恢复。

审计在权限确认前记录准备状态，权限裁决后、执行前记录允许或拒绝。执行前写入失败即阻止操作；执行后审计失败会终止子任务、返回真实部分进展和审计错误，不声称文件回滚。审计文件不进入 recall 归档，不随内存任务记录淘汰删除；`/subagents <ID>` 展示日志路径。explore 继续使用原有只读默认行为和归档格式。

## 状态和退出原因

| 原状态 | 事件 | 新状态 |
| --- | --- | --- |
| `CREATED` | 注册完成 | `QUEUED` |
| `QUEUED` | 获得执行槽位 | `RUNNING` |
| `CREATED` / `QUEUED` | 取消或截止时间已到 | `CANCELLING`，不执行模型或工具，清理确认后进入 `EXITED` |
| `RUNNING` | 接受正常结果或异常结果 | 清理完成并确认线程结束后进入 `EXITED` |
| `RUNNING` | 请求取消、到期或关闭 | `CANCELLING` |
| `CANCELLING` | 执行及取消清理线程均已结束 | `EXITED` |

阶段独立记录为 `IDLE`、`REQUESTING_MODEL`、`EXECUTING_TOOL`、`COMPACTING_CONTEXT`、`CLEANING_UP`。等待模型响应属于运行中的工作阶段，不模拟操作系统 CPU 时间片状态。

退出原因分为 `SUCCEEDED`、`FAILED`、`CANCELLED`、`TIMED_OUT`、`BUDGET_EXCEEDED`、`SHUTDOWN`。停止请求另记来源：用户取消、父轮取消、父作用域关闭、会话切换、超时或应用关闭。首次接受的停止来源不被后续停止请求覆盖。

完成结果和停止请求在控制块同一监视器下裁定。停止请求先被接受时，不允许迟到的成功覆盖停止结果；结果先被接受时，后续取消仍能推动清理，但不改写已选的完成原因。清理异常可将成功改为失败。结果至多发布一次，发布前由监督线程确认执行线程和取消清理线程均已结束，随后释放活动槽位。

## 取消与资源

正常模型流和摘要流都登记到控制块。登记与停止竞争时，登记方检查停止状态并立即关闭迟到的流；清除资源时必须按实例匹配，旧请求不能清掉新请求。工具上下文使用本次任务自己的进程引用和取消信号。

停止操作幂等，发出线程中断，并在独立、受监督的虚拟线程中关闭模型流和尽力终止受管工具进程，防止响应体关闭阻塞 TUI。执行线程在 `finally` 中再次进行幂等清理。Java 线程没有安全强杀机制，进程树终止也受平台权限约束。

总预算从接收任务开始，使用单调时钟判断。监督线程处理阻塞期间的超时；执行边界直接检查父取消和剩余时间；接受结果时再次检查截止时间，避免依赖监督线程的调度时机。取消宽限时间为 2 秒，超期保留活动槽位并标记清理超时，不将任务标记为已退出。

## 父作用域与会话

父轮取消立即通知所属任务，父执行作用域离开时取消异常遗留任务。界面收到取消结束事件，只意味着交互结束，不代表执行资源已释放。旧父轮持有自己的会话对象，迟到的工具结果只写回原会话；子任务中间消息始终不进入父会话。

新建会话或成功切换到不同会话时取消原会话活动任务；切换失败或切换到当前会话不取消。当前会话只能通过 `/subagents` 查询自己的任务结果。应用关闭先拒绝新任务，再取消活动任务并限时等待；重复关闭安全。

终端消费事件时同时处理 raw mode 的命令输入，允许 `/subagents [ID]`、`/help` 和 `/cancel`；命令不进入模型上下文。持续输出也检查按键，避免 Ctrl+C 和状态查询饥饿。其他命令在运行期间拒绝，防止重入对话或切换会话。权限确认不会接收运行命令的未提交尾部；轮次结束时未提交的输入移交空闲行编辑器继续编辑。

## 结果保留与统计

结果统计包含运行耗时、调查迭代数和服务端已返回的 token 用量。压缩请求计入时间和 token，单独的调查迭代预算不计摘要请求。缺失 usage 不按已知零用量展示；中断请求的未返回用量无法推算。第一阶段不实现 token 硬预算。

成功报告上限 16000 字符，截断明确标记；部分进展上限 4096 字符，错误摘要上限 512 字符，避免拆开 Unicode 代理对。退出后释放原始 prompt、消息、线程、流及父取消回调等引用，只保留身份、状态、统计及有界结果。

最多保留 32 条已退出记录，按完成顺序淘汰，不删除活动记录；读取结果不消费记录。记录只在内存保存，归档沿用原有文件格式，淘汰记录不删除归档。

## 验证边界

测试覆盖启动前取消、取消与流登记竞争、清除旧流、完成与取消竞争、清理延迟和清理异常、阻塞超时、预算耗尽、用量合并、记录淘汰、会话切换及迟到结果隔离；edit 的新建/修改预览顺序、独立授权、会话放行、拒绝/取消/超时、版本冲突、工具子集、无 UI、审计失败和父子事件归属。强制结束 JVM、操作系统拒绝终止进程、永久不响应取消的第三方代码均无法保证清理完成。
